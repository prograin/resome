# آمار هفتگی شاگردان

## راه‌اندازی

1. با `npm run auth:migrate` جدول‌های ثبت هفتگی را به دیتابیس اضافه کنید؛ این مهاجرت داده‌های قبلی را حذف نمی‌کند.
2. یک مقدار تصادفی و محرمانه با حداقل ۳۲ کاراکتر برای `CRON_SECRET` در محیط استقرار تنظیم کنید.
3. پروژه را روی Vercel مستقر کنید. زمان‌بندی `vercel.json` هر جمعه ساعت ۲۰:۳۰ UTC، معادل شنبه ساعت ۰۰:۰۰ تهران اجرا می‌شود.
4. برای اولین ثبت یا اجرای دستی، `npm run student:weekly` را اجرا کنید. روی سرورهای دیگر نیز همین فرمان باید با زمان‌بند میزبان، هفته‌ای یک‌بار اجرا شود؛ اجرای سرور توسعه به‌تنهایی زمان‌بند راه نمی‌اندازد.

مسیر زمان‌بندی `/api/cron/student-weekly/` فقط درخواست با هدر `Authorization: Bearer <CRON_SECRET>` را می‌پذیرد. Vercel این هدر را از متغیر محیطی تنظیم‌شده می‌فرستد. مقدار محرمانه نباید در کد، URL یا خروجی لاگ نوشته شود.

بعد از ثبت آمار، اجرای زمان‌بندی و فرمان دستی `student:weekly` رکوردهای امنیتی منقضی را نیز پاک می‌کنند: نشست‌ها و رکوردهای تأیید منقضی و شمارنده‌هایی که بیش از یک روز از انقضایشان گذشته است. داده‌های آموزشی و نشست‌های فعال حفظ می‌شوند.

## قواعد ثبت و نمایش

- هفته از شنبه ساعت ۰۰:۰۰ با منطقهٔ زمانی `Asia/Tehran` شروع می‌شود.
- هر اجرا تصویر ثابتی از آمار شاگردان فعال، به‌جز استاد و حساب‌های بن‌شده، ذخیره می‌کند. رتبهٔ کل فقط از میانگین امتیازهای دوره‌های متوسط و سخت محاسبه می‌شود؛ تعداد و ترتیب دوره‌ها شرط نیست.
- میانگین شخصی تمام امتیازها، تعداد دوره‌ها و تعداد ارزیابی‌ها تا لحظهٔ ثبت ذخیره می‌شوند؛ ستون‌های جریمه در نسخهٔ جاری صفر هستند. کارت‌ها مستقل از فیلتر زمانی نمودارند. قواعد در [منطق امتیاز و رتبه‌بندی](STUDENT-SCORING.md) آمده است.
- دورهٔ مبنا آخرین دورهٔ اختصاص‌یافته به شاگرد بر اساس شناسهٔ تخصیص است؛ تکمیل‌شدن دوره در انتخاب آن اثر ندارد. عنوان دوره همراه با رتبه ذخیره می‌شود.
- مقایسه فقط با ثبت هفتهٔ تقویمی قبل و نسخهٔ یکسان سیاست انجام می‌شود؛ اگر آن هفته ثبت نشده، تغییر هفتگی نمایش داده نمی‌شود. برای دوره نیز شناسهٔ تخصیص باید یکسان باشد.
- اجرای مجدد در همان هفته و با همان نسخهٔ سیاست دادهٔ ثبت‌شده را تغییر نمی‌دهد و رکورد تکراری ایجاد نمی‌کند. ثبت گروهی تراکنشی است و شکست هر بخش، کل ثبت همان نوبت را برمی‌گرداند. ثبت‌های سیاست قدیمی حفظ می‌شوند.
- اجرای ازدست‌رفته با اطلاعات امروز برای هفته‌های گذشته بازسازی نمی‌شود. تاریخ آخرین اجرای موفق در داشبورد مشخص است.
- پیش از اولین ثبت هفتگی، کارت‌ها آمار زنده و پیام انتظار برای اولین ثبت را نمایش می‌دهند. شاگرد تازه‌وارد تا ثبت هفتگی بعدی نیز سابقهٔ قابل مقایسه ندارد.
- نمودار، KPIها و جدول رتبه‌بندی داده‌های زنده را نشان می‌دهند؛ ثبت هفتگی مبنای مقایسه با هفتهٔ قبل است. افت ماهانه حذف شده؛ جاب مستقل روزانه پس از ۶۰ روز حساب را غیرفعال می‌کند و تاریخچه را نگه می‌دارد.
- اگر پس از ثبت هفتگی، دورهٔ جدیدی برای شاگرد اضافه شود، کارت دورهٔ فعلی و KPI رتبهٔ دوره به دورهٔ جدید اشاره می‌کنند. تا ثبت هفتگی بعدی، رتبهٔ زندهٔ این دوره بدون مقایسهٔ هفتگی نمایش داده می‌شود؛ رتبهٔ دوره‌های متفاوت با یکدیگر مقایسه نمی‌شود.

## بررسی

با تنظیم `STUDENT_TEST_DATABASE_URL` روی PostgreSQL آزمایشی و اجرای `npm run test:weekly`، مهاجرت ORM، رتبه بر اساس میانگین، سابقهٔ هفتهٔ قبل، محدودیت جدول، تقویم تهران، اجرای تکراری و بازگشت تراکنش ناموفق بررسی می‌شوند. `npm run test:scoring` فیلتر سطح دوره، ورود با اولین دورهٔ مجاز، حذف افت امتیاز، جایگاه‌های یکتا و جداسازی نسخه‌های سیاست را بررسی می‌کند. `npm run test:student:inactivity` مرز ۶۰ روز و رقابت با ثبت امتیاز را پوشش می‌دهد. تست‌ها دیتابیس موقت جدا می‌سازند و داده‌های واقعی را تغییر نمی‌دهند. ساختار ORM و دستورهای مهاجرت در [راهنمای معماری آکادمی](ACADEMY-ARCHITECTURE.md) آمده است.
