# راهنمای ویرایش فایل‌ها

کد منبع، محتوا و خروجی بیلد از هم جدا هستند. برای تغییر متن یا قیمت، فایل محتوای همان صفحه را ویرایش کنید؛ نیازی به دست‌زدن به کد نمایش نیست.

## متن و اطلاعات

| بخش                                 | مسیر                                                               |
| ----------------------------------- | ------------------------------------------------------------------ |
| متن خانه                            | `src/content/home/fa.json` و `en.json`                             |
| متن، قیمت و ویژگی‌های آموزش‌ها      | `src/content/academy/fa.json` و `en.json`                          |
| پرسش‌های آکادمی                     | `src/content/academy/faq.json`                                     |
| متن و پکیج‌های سفارش پروژه          | `src/content/order/fa.json` و `en.json`                            |
| پرسش‌های سفارش پروژه                | `src/content/order/faq.json`                                       |
| متن فوتر                            | `src/content/footer/fa.json` و `en.json`                           |
| عنوان و توضیحات سئو                 | `src/content/seo/fa.json` و `en.json`                              |
| دامنه، لینک‌ها، شماره تماس و موقعیت | `src/config/site.js`                                               |
| پروژه‌های قابل نمایش در سفارش پروژه | `src/pages/projects.js`                                            |
| متن منوها و دکمه‌های رزومه          | `src/content/ui/fa.json` و `en.json`                               |
| اطلاعات رزومه                       | `src/content/resume/fa/` و `en/`                                   |
| هر پروژهٔ رزومه                     | فایل اختصاصی در `src/content/resume/fa/projects/` و `en/projects/` |

نام‌ها و کلیدهای فنی مثل `private`، `group` و شناسهٔ پروژه‌ها را ثابت نگه دارید. قیمت‌ها در قسمت `plans` آکادمی و `packages` سفارش پروژه قرار دارند. هنگام افزودن پروژهٔ رزومه، فایل آن را در `projects.js` همان زبان هم وارد کنید تا ترتیب نمایش مشخص باشد.

## ظاهر و قالب

- `src/css/pages/`: استایل بخش‌های خانه، آکادمی، سفارش پروژه، تماس و رزومه.
- `src/css/components/`: استایل اجزای مشترک، مثل فوتر.
- `src/css/foundation/`: فونت، تنظیمات پایه و متغیرهای اولیه.
- `src/css/shared/`: قواعد مشترک، حالت روشن و تیره، واکنش‌گرایی و قواعدی که چند بخش را پوشش می‌دهند.
- `src/css/index.css`: ترتیب اتصال استایل‌ها. ترتیب آن را بدون بررسی تغییر ندهید؛ ترتیب قواعد روی ظاهر اثر دارد.
- فایل‌های `design` تنظیمات جدیدتر ظاهر هستند؛ فایل‌های `legacy` قواعد سازگاری موجود را نگه می‌دارند. هر بخش به فایل‌های کوچک تقسیم شده است.
- `src/templates/layout.html`: پوستهٔ اصلی صفحه.
- `src/templates/partials/`: هدر، پس‌زمینه، مودال‌ها و بخش‌های مستقل رزومه.

برای پیدا کردن یک جزء، کلاس آن را در `src/css/` جست‌وجو کنید؛ مثلاً `academy-plan__details` برای دکمهٔ جزئیات کارت‌های آموزش. آدرس عکس‌ها در استایل منبع برای خروجی `src/output.css` نوشته می‌شود؛ با جابه‌جایی فایل منبع نیازی به تغییر آدرس عکس نیست.

## رفتار صفحات

- `src/app/router.js`: جابه‌جایی بین صفحات و مدیریت URL.
- `src/app/theme.js`: حالت روشن و تیره.
- `src/app/locale.js`: زبان و راست‌چین یا چپ‌چین بودن.
- `src/app/modal.js`: مودال مشترک، فوکوس و بستن با Escape.
- `src/app/events.js`: رویدادهای منو و لینک‌ها.
- `src/pages/academy.js`: ورودی کوچک صفحه؛ ماژول‌های `src/pages/academy/` کارت آموزش، تب‌ها، مودال جزئیات و قالب صفحه را جدا می‌کنند.
- `src/pages/order.js`: ورودی کوچک صفحه؛ ماژول‌های `src/pages/order/` کارت خدمات، کارت پکیج، مودال امکانات و قالب را جدا می‌کنند.
- `src/resume/`: هر قسمت رزومه در ماژول خودش، از فیلتر و مهارت تا گالری و جزئیات پروژه.
- `src/updates.js`: بررسی نسخهٔ تازه و مودال بروزرسانی.
- `src/entries/`: ورودی‌های بیلد؛ مرورگر ماژول‌های منبع را جداگانه دانلود نمی‌کند.

## فایل‌هایی که خودکار ساخته می‌شوند

فایل‌های HTML ریشه و پوشه‌های مسیرها، `src/app.js`، `src/chunks/`، `src/styles/`، `src/output.css`، `site-version.json` و `dist/` خروجی هستند. آن‌ها را مستقیم ویرایش نکنید. ابزارهای آمادهٔ Tailwind در `src/css/vendor/` هم فایل کامپایل‌شده‌اند؛ تغییر ظاهر را در استایل بخش مربوط انجام دهید.

بعد از ویرایش:

```powershell
npm run format
npm run package
```

برای بررسی کامل مرورگر، سرور محلی را روی پورت ۴۱۷۳ اجرا کنید و `npm run test:browser` را بزنید. `npm run test:performance` و `npm run test:updates` هم سرعت اولیه و چرخهٔ بروزرسانی را بررسی می‌کنند.

فایل‌های منبع قابل ویرایش باید حداکثر ۲۵۰ خط باشند. `npm run check:structure` این محدودیت را بررسی می‌کند و همراه `npm run package` هم اجرا می‌شود. اگر فایلی بزرگ شد، مسئولیت تازه را به ماژول مستقل منتقل کنید. خروجی‌های خودکار و ابزارهای کامپایل‌شدهٔ Tailwind در این محدودیت حساب نمی‌شوند.
